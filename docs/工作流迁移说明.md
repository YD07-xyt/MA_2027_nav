## 4. 首轮工具链契约

以下命令已在首轮实现，细节与基线操作见 `docs/TOOLCHAIN.md`。

```bash
# 工作目录：/home/xyt/map/src/MA_2027_nav
```

### 4.1 静态入口必须检查什么

1. 工具存在且版本符合配置；缺依赖明确返回非零，不自动安装。
2. 扫描范围存在且非空；必须覆盖 `src/`、配置和适用入口，不能因模板 `modules/` 不存在而空跑通过。
3. 一方 C++ 文件格式只读检查，覆盖 `.h/.hpp/.hh/.hxx/.cpp/.cc/.cxx`；launch 使用 Python AST 解析，不导入执行。
4. 对明确纳入的 `.yaml/.yml` 检查语法和重复键；额外纳入的 `.rviz` 若按 YAML 处理，应单独列出范围。
5. 核心区域 ROS 引用、重型公开头和 Eigen 表达式进行初筛，记录规则覆盖限制；CMake 文本扫描不能宣称完整 target 图已验证。
6. XML 仅按已声明文件类型做语法检查；`package.xml` 不作为行为树文件解释。
7. 工具测试验证成功与失败路径，检查非零返回、未授权构建拒绝、源码及 Git 配置不被修改。

排除 `.git/`、`3rd/`、`build/`、`install/`、`log/`、缓存、大型地图和数据。对一方测试代码按相应规则扫描，不以“测试”为理由统一排除。

扫描路径必须限制在 NAV 仓库内，拒绝通过父目录或符号链接扩展到其他代码项目。工具的默认根路径从自身所在仓库解析，不向上查找 `/home/xyt/map/src` 中的包。

“只读”指不改变源码、配置、索引、历史或 Git 配置；临时夹具和报告写入明确的临时/产物目录。静态阶段不调用 CMake、编译器驱动的生成步骤、colcon、运行中的 ROS 节点或 launch。

### 4.2 存量问题如何处理

首轮先全量扫描形成真实基线，按规则、相对路径和稳定问题标识登记。基线记录问题，不代替修复，也不改变 `.clang-tidy` 来掩盖诊断。

- 新增文件：适用静态规则全部通过。
- 已有文件：检查本次变化引入的新问题；原有问题仍列在报告中，编辑相关代码时逐步处理。
- 格式：新增文件检查完整文件；已有文件检查本次改动行，不为局部任务格式化整仓库。支持只有未跟踪文件、文件重命名和无改动等情况。
- 基线新增或范围扩大须说明原因；零文件或规则执行器缺失不作为成功。
- 全量扫描存在历史缺陷时返回失败，增量门禁通过时仅称“本次改动静态门禁通过”，同时展示存量问题。

### 4.3 结果分类

每次报告分别列静态、编译、运行测试、Sanitizer、性能和实机项：通过、失败、未验证、不适用。未授权项写“未验证”，不计为通过。

`PASS` 只针对明确声明的验收范围。已有离线可执行程序尚未登记/运行时，测试项保持未验证；没有 CTest 用例时不能输出“单测全部通过”。
