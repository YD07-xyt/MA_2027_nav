# 接口契约

触发：新增公开接口，或改变调用方可观察的输入/输出、跨模块数据、状态、错误、所有权、时间或性能契约。内部变量、私有函数或实现方式变化且保持既有契约时，无需额外确认。

先查当前声明、调用方、配置及用户要求。用户已明确确认的契约不重复询问；出现多个合理选择且现有证据不能确定时，只暂停依赖该选择的实现，提交最小草案和调用方影响。任务尚未说明契约时，不能仅凭“修复/优化”的概括要求自行选择新的失败或退化策略。

## 确认内容

给出当前公开声明位置（通常为模块 `include/`）的类型/方法草案及调用方影响；协议或配置语义变化给出相应字段和行为差异，不强行新增 C++ 接口。只回答适用项，不适用项写 `N/A`，不猜测数值。

| 项目 | 必须明确 |
| :--- | :--- |
| 输入 | 合法范围、单位、坐标系、由谁校验 |
| 时间 | 时钟域、事件时间/接收时间、外部传入与离线回放语义 |
| 所有权 | 借用/持有、读写者、指针与视图失效时机 |
| 状态 | 构造/init/set_param/reset 的等价性、调用顺序、历史状态 |
| 结果/失败 | 返回值含义、失败是否保留旧路径/样条、部分输出是否有效 |
| 并发 | 允许的同时调用、同步责任、快照一致性 |
| 性能 | 受约束阶段、最大容量、超限策略、测量方式 |
| 兼容 | 影响的调用方、参数、ROS 协议及有意行为变化 |

完成条件：调用方可据此正确使用；影响实现的未决选择已确认。稳定契约写在公开声明旁，跨模块关系写架构索引。

## 设计与验收

- 优先具体类和值语义，抽象对应真实变化需求。
- 多阶段结果优先成功后整体提交；继续旧轨迹或部分提交属于业务选择，需确认。
- 借用优先 const 引用/span，共享只读快照考虑 shared_ptr<const T>；具体变更须核对当前调用方。
- 类型选择须符合当前 C++ 标准、依赖及调用方兼容性；不为使用 span/string_view 或快照而批量改接口、增加共享所有权或升级语言标准。
- 按变化验证正常、边界、失败后状态、重复初始化/reset、快照/借用、并发及容量场景，不为未变行为机械增加测试。编译通过只证明编译范围，未授权的动态检查明确标记未验证。
