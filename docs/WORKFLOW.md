## 2. 契约

公开接口、状态、错误、所有权变化按 [接口规则](rules/interfaces.md) 提出最小草案。代码可回答的先查代码；单位、时钟、退化或容量策略仍不清楚时询问用户，只暂停依赖该决策的实现。

完成条件：实现依赖的行为选择均有来源或已确认；已有契约内的局部修改直接执行。

## 3. 修改与验证

按周边风格最小修改，先运行静态入口：

```bash
./scripts/verify.sh
./scripts/verify.sh --static-only --report .cache/verify/latest.json
```

| 修改类型 | 证据要求 |
| :--- | :--- |
| 文档、工具 | 引用事实/路径核对；静态入口；工具行为变化的隔离正反例 |
| YAML、launch | 语法/重复键或 AST 检查，核对实际加载及路径来源 |
| 核心逻辑、接口 | 静态入口、相关调用方与边界场景；构建/测试需授权 |
| ROS | 转换、发布订阅与并发边界；静态初筛不能替代消息运行验证 |
| CMake | 授权后检查真实编译/链接选项与依赖，预设名称不代表生效 |
| 并发、性能 | 授权后的覆盖场景和测量；分别记录 Sanitizer 与同环境性能基线 |

当前仅提供静态验证模式。`--with-ros2`、`--tsan`、`--benchmark`、`--build` 均会被拒绝，不触发构建。工具细节与存量基线见 [TOOLCHAIN.md](TOOLCHAIN.md)。

完成条件：本次适用检查全部通过；缺依赖、未授权及未接入项标记未验证，不能据静态通过宣称项目整体可用。

完成条件：明确 `PASS` 或 `NEEDS_FIX` 及其范围，并逐项区分静态、构建、运行测试、Sanitizer、性能和实机证据。版本控制写操作由用户执行。
