# NAV 开发工作流

根 [AGENTS.md](../AGENTS.md) 管工作区、授权与比赛逻辑限制；本文件统一执行顺序、记录和交付。参考其他项目时，以 NAV 实际入口与验证能力为准。

## 1. 事实与范围

先看 Git 状态、实际入口、配置与调用方，区分当前路径和历史方案，保留已有用户修改。内部明确模块、目标、修改范围、允许的行为变化与验收范围，不额外生成计划文件。

完成条件：每项修改都能对应用户目标和事实来源；只读问答直接交付结论。

## 2. 契约

按 [接口规则](rules/interfaces.md) 判断是否触发确认。公开接口或可观察契约变化给出最小草案及调用方影响；既有契约内的实现直接执行，用户已经确认的行为不重复确认。

代码可回答的先查代码；单位、时钟、退化或容量策略仍有待决项时询问用户，只暂停依赖该决策的实现。

完成条件：实现依赖的行为选择均有来源或已确认。

## 3. 修改与验证

按周边风格最小修改。文档、注释、格式等低影响修改不强制新增测试；算法、状态或工具行为变化选择能观察输入/输出和失败行为的场景。

静态入口：

```bash
./scripts/verify.sh --static-only
# 如需保存报告：
./scripts/verify.sh --static-only --report .cache/verify/latest.json
```

默认 `./scripts/verify.sh` 与 `--static-only` 均不构建。当前 `--with-ros2`、`--tsan`、`--benchmark`、`--build` 均被拒绝；不能照搬参考项目的完整验证命令。工具范围与存量基线见 [TOOLCHAIN.md](TOOLCHAIN.md)。

| 修改类型 | 证据要求 |
| :--- | :--- |
| 文档、规范 | 路径、链接、命令及代码事实核对；规范/工作流变化执行静态入口 |
| 验证工具 | 静态入口及隔离正反例，检查错误拒绝、只读性与失败传播 |
| YAML、launch | 静态入口、语法/重复键或 AST 检查；核对实际加载链路及路径基准 |
| 核心逻辑、接口 | 静态入口、相关调用方与正常/边界/失败场景；动态验证按授权执行 |
| ROS | 静态入口、转换、发布订阅与并发边界；静态初筛不能替代消息运行验证 |
| CMake | 静态核对；授权后检查真实配置、编译/链接选项与依赖 |
| 并发、性能 | 静态核对共享状态/受约束阶段；授权后验证真实场景，分别记录 Sanitizer 与同环境性能基线 |

授权范围按根规范执行。缺依赖、未授权及未接入项标记未验证，不擅自安装依赖或修改环境来掩盖失败。构建若获授权，记录具体命令、范围、结果与关键失败日志，区分本次引入和已有问题；无法归因时写明。

完成条件：本次适用检查均有结果；命令成功只证明其实际覆盖范围。不能据静态通过宣称项目整体可用，不能仅凭基准运行成功宣称性能改善。

## 4. 审查、记录与交付

核对本次差异及受影响链路，不把用户已有修改算作本次变更。接口语义写在公开声明旁，跨模块关系更新架构索引。

### 记录触发条件

| 任务 | 记录与交付 |
| :--- | :--- |
| 普通问答、代码解释 | 直接回答，无需新建记录或输出修改模板 |
| 只读审计 | 输出范围、发现、证据和未验证项；仅在用户要求时落盘 |
| 错别字、局部注释、纯格式等低影响修改 | 简述文件、改动及检查，不强制记录 |
| 算法、状态、公开接口、配置语义、依赖、启动或通信变化 | 事后改造记录，说明行为保持与有意变化 |
| 规范/工作流、验证工具行为变化及非局部重构 | 事后改造记录，说明规则或工具行为影响 |

上表后三类涉及文件修改；用户明确要求不写记录时从其要求。记录路径为 `docs/ai_refactor_records/<YYYYMMDD>_<task_name>.md`，用户指定路径时从其要求。该目录当前由 Git 忽略，属于本地审计材料；需随代码保留的规范、契约与架构结论写入正式文档，不只留在本地记录中。

### 事后记录模板

单 Agent 也可使用以下栏目，栏目表示工作阶段，不表示已启动子 Agent。不适用项标记 `N/A`，不机械填充无关检查。

```md
# <任务名称> 改造记录

## User Intent
用户目标与关键约束。

## Scope
允许修改的范围。

## Out of Scope
本次不处理的内容。

## Explorer Findings
### Files inspected
### Active logic path
### Data flow
### Risk notes
### Recommended modification boundary

## Modifier Changes
### Files changed
### Key changes
### Behavior preserved
### Behavior intentionally adjusted
### Notes

## Auditor Review
### Checks performed
逐项列出检查、命令、结果与证据范围；使用 PASS / NEEDS_FIX / NOT_VERIFIED / N/A。
### Issues found
### Final result
结论、适用范围及未验证项。
```

涉及比赛验证逻辑时，记录中明确写“本次修改涉及比赛验证逻辑，采用最小改动策略。”记录应在修改后补充，不作为执行前的阻塞步骤。

### 结果与最终回复

- `PASS`：声明范围内适用检查均通过。
- `NEEDS_FIX`：存在明确失败或未解决缺陷。
- `NOT_VERIFIED`：缺证据、未执行或能力未接入，不能据此断言通过或失败。
- `N/A`：与任务无关的检查。

最终回复只列适用内容：修改摘要与文件、保持/有意改变的行为、检查命令和结果、记录路径、未解决项及带范围的结论。必须区分静态、构建、导航运行测试、Sanitizer、性能和实机证据；可合并未验证项。未获构建许可时使用根规范要求的说明。

可以报告 `PASS（本次规范修改与静态检查范围）；构建、导航运行与实机 NOT_VERIFIED`，不能将必要行为验证未完成的任务表述为“整体验收通过”。无需为普通问答附构建声明。

完成条件：变更可追溯，结果与证据一致，适用的记录已补充。

## 5. 用户明确要求时的多 Agent 流程

仅在根规范规定的明确授权条件下启用，默认顺序为 `Explorer → Modifier → Auditor`；未授权时由单 Agent 完成事实核对、修改与复核。

- **Explorer（只读）**：核查实际启用入口、调用链、配置来源、共享状态与用户禁区；按任务核对节点注册、blackboard 读写者、topic/QoS/频率及历史分支。返回文件/位置、事实、风险和修改边界，不修改任何文件；由主 Agent 汇总进事后记录。
- **Modifier**：依据探索结果和已确认目标最小修改，保持优先级与数据流。发现事实不全时先补查；需要扩围或新的行为决策时按契约规则确认。
- **Auditor（只读）**：独立查看 diff，重新搜索关键符号，复核范围、调用链与行为优先级，执行授权范围内检查。按第 4 节返回带范围的结果，不直接修代码。

发现问题后由 Modifier 定点修复，Auditor 复核受影响部分；主 Agent 汇总真实执行结果与未验证项，不将角色栏目冒充独立审计证据。
