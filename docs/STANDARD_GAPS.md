# NAV 规范与验证缺口

现状以本仓库源码为准。静态迁移只接入规则与工具，不将目标能力写成已完成。

| 项目 | 当前事实 | 完成条件 |
| :--- | :--- | :--- |
| 存量初筛 | 首次基线有 14 个候选：11 个重型公开头 include、3 个 Eigen 表达式模式 | 按接口/返回类型逐项人工判断，在独立任务处理；测试 include 不等于生产接口缺陷 |
| 格式 | 已有一方代码不完全符合当前 clang-format 18 配置 | full-scan 报告现状；相关修改逐步整理，不全仓格式化 |
| 构建模式 | 根 CMake 固定 Release/LTO；无核心/ROS 开关 | 经确认接入并核对真实选项，授权后验证 |
| 测试闭环 | `bench_nav_pipeline` 已提供无副作用自检与离线基准闭环；其余离线程序尚未注册 CTest 且部分会写图片/数据 | 确认输入、断言、退出和副作用，接入确定性 CTest 闭环 |
| clang-tidy/Sanitizer | 入口当前只静态解析，没有新构建数据库或插桩验证 | 授权后逐模式接入；旧 build 缓存不代表当前分支 |
| 依赖隔离 | 名称扫描只初筛 ROS，引入关系未做完整图验证 | 核对实际 target 传递依赖、公开头与循环依赖 |
| ROS 编排 | GlobalPlanner2d 尚含业务编排与状态维护 | 独立任务确认接口与职责后逐步处理 |
| 配置路径 | planner.yaml 内含 src/navigation/... 历史相对路径 | 确认仓库内资源/部署路径及相对基准，单独调整配置与测试 |
| 配置语义 | 静态可解析不代表范围、单位、必填和退化合法 | 明确不变式，再由真实 yaml-cpp 加载场景验证 |
| 并发/性能 | 核心离线模块已有 `bench_nav_pipeline` + `scripts/compare_bench.py` 改前/改后对比基线；ROS 回调组、TSan/ASan 并发插桩与高频分配尚未系统验收 | 补齐真实 ROS 共享状态测试、Sanitizer 与按阶段分配测量 |
| 文档证据 | 基线版本校验器默认输入缺失；最终工作区 docs/tools 的 9 个文件处于删除状态 | 先确认旧工具去留，需要时以独立夹具验证路径、输入/输出和失败传播 |
| 实机 | 本轮没有运行或实机证据 | 按配置版本与场景记录，不以静态通过替代 |

基线来源和扫描限制见 [TOOLCHAIN.md](TOOLCHAIN.md)。迁移完成情况见 [工作流迁移说明.md](工作流迁移说明.md)。
