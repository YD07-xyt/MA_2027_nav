# NAV 源码规则

修改前读取根 `AGENTS.md` 和 `docs/WORKFLOW.md`。本文件约束后续改动，存量偏差见 `docs/STANDARD_GAPS.md`。

## 模块边界

- 核心目录为 `utils/`、`map/`、`planner/`；新增实现沿现有依赖方向，按 `docs/ARCHITECTURE.md` 核对调用与链接，避免循环依赖。
- ROS 入口为 `ma_nav.cpp`，ROS 适配与当前编排位于 `ros2/`；修改后者读取其专项规范。核心新增代码不引入 ROS 消息、Node 或 ament 依赖。
- `test/` 是一方离线验证代码，仍需检查；现有程序兼有可视化、Benchmark、回放与数据输出职责，先确认输入、副作用和退出条件。
- 公开头暴露调用方必需的类型与声明。重型实现依赖优先保留在实现文件；现有公开 PCL/OsqpEigen 类型属于待评估项，不因本规则批量整改。

## 接口与数值

- 公开接口或可观察行为变化先按 `docs/rules/interfaces.md` 确认契约；调用者不知道的 setter 顺序、失败后状态和视图失效条件必须写明。
- Eigen 表达式保存时显式物化为值类型或经确认的视图，说明借用生命周期；静态正则只是疑似表达式初筛。
- 连续数据只读借用优先 span，字符串借用优先 string_view；需要拥有或管理容量时使用拥有型类型。
- 高频分配要求明确函数、阶段、容量及超限策略。预分配不等于全调用链零分配，线程池和求解器内部需独立测量。
- 跨线程状态说明唯一写入者、锁/快照与借用边界；shared_ptr 管理寿命，不自动保证对象线程安全。

## 风格与验收

沿周边命名与现有 `.clang-format`、`.clang-tidy`。运行 `./scripts/verify.sh` 检查增量；已有代码只修本任务范围，任何配置、算法及通信变化按根规范确认并留记录。
